# Supabase 설정

클라우드 세이브 + 랭킹용. **게임 본체는 이것 없이도 그대로 돌아간다** — 클라우드는 켜고 끄는 기능이지 필수가 아니다.

## 왜 이렇게 갈랐나

세이브 백업과 랭킹은 다른 물건이다.

| | 검증 | 쓰는 주체 | 호출 빈도 |
|---|---|---|---|
| **세이브** (`saves`) | 안 한다 | 클라이언트 (RLS 로 본인 것만) | `save()` 마다 (디바운스) |
| **랭킹** (`scores`) | 한다 | **Edge Function 만** | 기록 갱신 때만 |

세이브를 조작해 봐야 본인 게임만 이상해진다. 거기에 검증을 걸면 밸런스 패치 때마다 정상 플레이어가 세이브를 잃는다.
남과 비교되는 숫자만 지키면 된다.

그리고 이 분리 덕에 **서버 함수가 거의 안 불린다.** 탑은 월 1회, 나락은 주 1회로 게임이 강제하므로
기록이 갱신될 일 자체가 드물다. 플레이어 100명이 매주 제출해도 월 500회 수준이다.

## 검증이 막는 것 / 못 막는 것

**막는 것** — 게임 규칙상 불가능한 값. 예: 지난주에 40심층이던 사람이 이번 주에 200심층.
나락은 주 1회이므로 서버가 이걸 **확실히** 안다. 게임의 입장 제한이 그대로 검증 근거가 된다.

**못 막는 것** — 전투 승패 조작, 아이템 스탯 위조, 규칙 경계 안에서 천천히 부풀리기.

> **"조작 방지"라고 말하면 안 된다. "개연성 검사"다.**

## 설치

### 1. 프로젝트 만들기 (직접)

1. supabase.com 가입 → **New project**
2. Region: **Northeast Asia (Seoul)**
3. Database Password 는 안전한 곳에 보관 — 이 프로젝트에서는 안 쓴다

### 2. 구글 로그인 켜기 (직접)

Authentication → Providers → **Google** 활성화.

★★ **익명 로그인은 일부러 끈다.** 처음엔 익명으로 만들었다 — 화면 한 번 안 띄우고
랭킹에 참여시킬 수 있어서다. 그런데 **브라우저 저장소가 지워지면 계정이 통째로 사라진다.**
iOS PWA 는 며칠 안 쓰면 실제로 정리한다. 복구 코드도 「코드를 잃으면 끝」이라 문제를 미룰 뿐이었다.

이메일+비밀번호는 설정은 제일 쉽지만 Supabase 내장 메일 발송이 **시간당 몇 통 수준이고
공식적으로 테스트용**이라 비밀번호 찾기가 사실상 안 된다.
구글은 메일 발송이 필요 없고 복구를 구글이 책임진다. (자세한 경위는 `docs/HANDOFF.md` §19.3)

⇒ 클라우드에 올리려면 로그인해야 한다. 그게 의도한 것이다.
   `node tools/supacheck.mjs` 가 «익명 꺼짐 + 구글 켜짐» 을 확인한다.

### 3. 스키마 적용

SQL Editor 에 [`001_init.sql`](001_init.sql) 전체를 붙여넣고 Run. 두 번 실행해도 안전하다.

### 4. RLS 전수 확인 (필수)

`001_init.sql` 맨 아래 주석의 쿼리를 실행한다. **결과가 0행이 아니면 배포하면 안 된다.**

publishable 키는 브라우저에 그대로 실려서 100% 공개다. RLS 를 안 켠 테이블 하나가 곧 전체 유출이다.

### 5. 키 전달

Settings → API 에서:

| 키 | 공개 여부 | 쓰는 곳 |
|---|---|---|
| Project URL | 공개 OK | `src/net/config.js` |
| publishable (구 anon) | **공개 OK** | `src/net/config.js` |
| secret (구 service_role) | **절대 공개 금지** | Edge Function 런타임이 환경변수로 자동 주입 — 사람이 만질 일이 없다 |

앞의 둘만 있으면 된다. secret 키는 어디에도 붙여넣지 마라.

## 계정 복구

**구글이 책임진다.** 따로 만들 것이 없다.

> 예전 계획(익명 로그인 + 복구 코드)은 버렸다. 익명은 브라우저 저장소가 지워지면
> 계정이 사라지고, 복구 코드는 「코드를 잃으면 끝」이라 문제를 미룰 뿐이었다.
> 그래서 §19.3 에서 구글 로그인으로 갈아탔다.
>
> 갈아탈 때 걸린 함정 둘: **익명 시절 세션이 저장소에 남아 `signedIn()` 이 참이라
> 구글 로그인 화면이 영영 안 떴다** (이메일 유무로 갈라 옛 세션을 버린다), 그리고
> 계정 전환에는 `prompt=select_account` 가 **반드시** 필요하다.

## 운영

- **keep-alive** — 무료 티어는 유휴 시 프로젝트가 멈춘다. GitHub Actions 로 매일 `rpc/ping` 을 친다.
  단, GitHub Actions 의 schedule 은 **저장소가 60일간 비활성이면 자동 비활성화된다.**
  커밋이 뜸해지는 시기에 조용히 멈추므로 외부 크론을 하나 더 두는 편이 안전하다.
- **flagged 확인** — `rejections` 테이블에 B등급(총량 상한 초과) 원본이 남는다.
  오탐이면 `scores.status` 를 `'ok'` 로 되돌린다.
